## Step 1: Reproduce the proxy and backend failure

I issued:

```powershell
$targets = @(
  'https://kasm.<YOUR_BASE_DOMAIN>/',
  'https://kasm.<YOUR_BASE_DOMAIN>/api/__healthcheck',
  'https://192.168.78.10/api/__healthcheck'
)
foreach ($target in $targets) {
  curl.exe -sk --max-time 10 -o NUL -w '%{http_code}|%{remote_ip}|%{time_total}' $target
}
```

The command exited `0` after printing:

```text
https://kasm.<YOUR_BASE_DOMAIN>/|502|192.168.85.2|3.134773
https://kasm.<YOUR_BASE_DOMAIN>/api/__healthcheck|502|192.168.85.2|3.176288
https://192.168.78.10/api/__healthcheck|000||10.016189
```

The direct timeout rejected an NPM-only fault.

## Step 3: Establish the capacity timeline

I issued:

```bash
journalctl --since '2026-07-29 22:00:00' --no-pager --grep 'Thin pool|I/O error|io-error|No space|out of data|ssd--lvm2'
```

It returned exit code `0`:

```text
Jul 29 22:05:09 purple-server dmeventd[352]: WARNING: Thin pool ssd--lvm2-ssd--lvm2-tpool data is now 90.02% full.
Jul 29 22:09:39 purple-server dmeventd[352]: WARNING: Thin pool ssd--lvm2-ssd--lvm2-tpool data is now 95.10% full.
Jul 29 22:24:09 purple-server dmeventd[352]: WARNING: Thin pool ssd--lvm2-ssd--lvm2-tpool data is now 100.00% full.
```

The SSD returned SMART `PASSED`, zero reallocated sectors, zero uncorrectable errors, & zero CRC errors during the live check. I retained no raw SMART output here because the documentation standard routes raw `smartctl` captures to the hardware inventory.
