**Created:** 2026-10-31

I replaced Executor 1.6.10 with Executor 2.0.0-beta.34, the newest beta, published that morning. I ran the two side by side, rebuilt all twelve integrations as apps, tested each one, moved the five agent clients, and then removed Executor 1 with its data.

## What Executor 2 Is

Executor 2 is not an upgrade of the same server. The self-host image keeps the `ghcr.io/usefulsoftwareco/executor-selfhost` name but runs a different program: one container with a PGlite database, workerd for app code, organizations and Better Auth sign-in, listening on 4400 with its data under `/app/data`. Integrations become apps, and the MCP endpoint exposes six fixed tools, `skills`, `search`, `describe`, `call`, `execute` and `resume`, in place of Executor 1's per-integration search tools. The repository's import from Executor 1 belongs to the hosted cloud service. Self-host has no migration path, so I recreated each integration from the live inventory.

5. I created Nginx Proxy Manager proxy host 37 through its API as a copy of host 27's settings: certificate 1, Force SSL, HTTP/2, WebSockets, exploit blocking, and the 3,600-second streaming timeouts. Upstream `192.168.40.39:4400`.
6. From `ubuntu-dev`, the name resolved to `192.168.85.2`, HTTP redirected to HTTPS, the certificate verified, `/health` returned `{"status":"ok"}`, and an unauthenticated POST to `/mcp` returned `401`.

## Client Cutover

I pointed `executor` in both Claude Code profiles and all three Codex profiles at `https://executor.alphasecunited.com/mcp`. Claude Code reported `Status: ! Needs authentication` and Codex `Not logged in`. A probe of the sign-in path returned the protected-resource metadata, PKCE `S256`, and a registered public client for a `http://localhost:53682/callback` redirect.

Writing the two non-default Codex profiles broke them in T3 Code. `~/.codex_alt/config.toml` and `~/.codex_personal/config.toml` are T3 shadow-home symlinks to `~/.codex/config.toml`. At 16:00:29 add-mcp replaced each link with a regular file, about half a second apart, and from 16:19:56 T3 logged `Failed to create provider instance` for `codex_codex_alt` and `codex_personal`, "already exists and is not a symlink". All three files had the same SHA-256, so I deleted the two copies and relinked them to `~/.codex/config.toml`. Afterwards `codex mcp get executor` with either profile's `CODEX_HOME` read the Executor 2 URL through the link. T3 rebuilds a failed instance only when its settings change or the server restarts.

- `docker compose down` in `/opt/docker/executor` removed container `executor` and network `executor_default`. I deleted the `executor-selfhost:latest` image (`sha256:ea8b4d10...`).
- I deleted `/opt/docker/executor`, 85 MB with `data.db` and both key files, and `/opt/docker/executor-v1-backup-2026-10-11`, 110 MB holding an image tarball and a state tarball from 2026-10-11 that no record mentioned. I keep no backups, and both held only Executor 1.

- I deleted UniFi DNS record `6a94416df9e5db24858d3005`. The gateway resolver at `192.168.40.1` no longer answers for the name.

On `docker-blue`, 1,133 MB was available afterwards, so CT 108 needed no memory change.
